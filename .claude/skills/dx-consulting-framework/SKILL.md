# DXコンサルティング診断フレームワーク

「DXはシステム導入では終わらない」という考え方をベースに、案件・提案を6つの視点で見る。ツール導入の有無ではなく、業務・組織・成果への波及まで見るのが狙い。

**背景となる考え方**：DXの本質的な難所は「作ることはできた。でも人・組織・業務が変わらず、成果につながらない」ところにある。DX成熟度を測るときは「どんなツールを導入したか」ではなく、導入後に業務がどう変わったか／誰の仕事が減ったか／誰の負担が増えたか／組織の役割が変わったか／現場に定着したか／売上・コスト・生産性・CXへ効果が出たか、まで見る。

---

## ① 6視点診断

**用途**：DX/業務改善案件（自分の実績整理、クライアントのAI活用相談、スポット診断サービスの成果物）を6視点で棚卸しする

**6つの視点**
1. **業務**：どの業務がどう変わったか（工程が減った／増えた／移動した）
2. **人**：誰の負担が減り、誰の負担が増えたか
3. **組織**：役割分担・意思決定プロセスは変わったか
4. **技術**：導入したツール・システムは何か（あくまで手段として扱う）
5. **定着**：現場に実際に定着したか、形骸化していないか
6. **成果**：売上・コスト・生産性・CX（顧客体験）のどれに、どう効果が出たか

**プロンプト**
```
以下のDX/業務改善の取り組みについて、業務・人・組織・技術・定着・成果の
6視点で整理してください。

【取り組みの概要】
（何をしたか、背景も含めて貼る）

【出力形式】
・業務：何がどう変わったか
・人：誰の負担が減り、誰の負担が増えたか
・組織：役割分担や意思決定プロセスの変化
・技術：導入した手段（あくまで手段として、過大評価しない）
・定着：現場に定着したか。形骸化のリスクはないか
・成果：売上/コスト/生産性/CXのどれに効果が出たか（数字があれば併記）
・総合評価：良かった点と、次に改善するとしたら何か
```

**ポイント**：「技術」の視点を最初に聞かない。ツール導入の話から入ると手段が目的化しやすいため、業務→人→組織の順で聞いてから技術に触れる。
