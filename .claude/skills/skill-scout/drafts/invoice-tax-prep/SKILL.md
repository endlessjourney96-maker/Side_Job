# 副業 請求書・確定申告下ごしらえキット（ドラフト）

`gig-work-kit`・`spot-consulting-kit`は「確定申告の基準（20万円超で必須、インボイス制度の影響）」を知識として持っているが、実際に毎月発生する「請求書・見積書を作る」「年末に経費を仕分ける」という**作業**までは扱っていない。このギャップを埋めるためのキット。

**共通ルール**：ここで作るのはあくまで「書類の下書き」「仕分けのたたき台」まで。実際の送付・申告書の提出代理はユーザー本人（必要に応じて税理士）が行う。税務判断の最終確認は必ず自分で行う（`spot-consulting-kit`の「外部への問い合わせ返信・請求書送付は、AIが勝手に実行しない」原則を踏襲）。

**前提データ**：`spot-consulting/収益トラッカー.md`（問い合わせ日・経路・商品・金額・ステータスを記録済み）を主な入力とする。

---

## ① 請求書・見積書のテンプレ化

**用途**：毎月同じ形式で発生する請求書・見積書作成を、1回のテンプレ確定後は一言で済ませる

**やり方**
1. 初回のみ、請求書に必要な項目（発行者情報・取引先名・品目・金額・税区分・インボイス登録番号の有無・支払期日・銀行口座）を確定し、雛形として保存する
2. 以降は「今月分の請求書を作って」と頼むだけで、`収益トラッカー.md`の該当月の確定済み案件を雛形に当てはめて下書きを作る
3. 送付前に、金額・取引先名・税区分だけは必ず自分の目で確認する（AIの仕事はフォーマットへの当てはめまで）

**プロンプト**
```
以下の雛形とデータから、今月分の請求書（下書き）を作ってください。

【請求書の雛形】
（発行者情報・項目・税区分・支払期日などのフォーマットを貼る）

【今月の確定済み案件（収益トラッカーより）】
（案件名・取引先・金額・完了日などを貼る）

【注意点】
・雛形にない項目は追加しない
・インボイス登録番号の有無や税区分の判断はせず「要確認」として明記する
・取引先名・金額は入力データをそのまま使い、推測で補完しない
```

**ポイント**：税区分（課税/非課税、インボイス対応の有無）はユーザー自身の状況に依存するため、AIに判断させず「要確認」として必ず立ち止まらせる。

## ② 経費・収入の仕分けたたき台

**用途**：確定申告の準備として、収入・経費を申告書の区分に仕分けるたたき台を作る

**やり方**
1. `収益トラッカー.md`の売上記録と、手元の経費メモ（領収書の一覧など）を用意する
2. Claudeに下のプロンプトで投げ、「売上」「経費（科目別）」の仕分けたたき台を出してもらう
3. 科目の妥当性・計算結果は必ず自分で（不安な場合は税理士に）確認してから使う

**プロンプト**
```
以下は副業の売上記録と経費メモです。確定申告の準備として、仕分けのたたき台を作ってください。

【売上記録】
（収益トラッカーの該当期間分を貼る）

【経費メモ】
（領収書・支出の一覧を貼る）

【出力形式】
・売上合計
・経費（科目別、例：通信費／消耗品費／外注費など）の仕分け案と小計
・不明・判断が難しいもの（「要確認」として明記）
・売上－経費の概算（あくまで下書きである旨を明記）
```

**ポイント**：科目の割り振りは税務判断そのものなので、AIの出力はあくまで「候補」。最終的な仕分けは自分（or 税理士）が確定する。

## ③ 確定申告の要否チェックリスト

**用途**：年末〜年明けに「今年は確定申告が必要か」を一度棚卸しする

**やり方**
1. 今年の副業売上・経費の概算（②の結果）を用意する
2. 本業の有無、他の副業の有無などの前提条件も合わせてメモする
3. Claudeに下のプロンプトで投げ、要否判定のチェックリストを出してもらう

**プロンプト**
```
以下の情報から、副業の確定申告が必要かどうかの判断材料を整理してください（最終判断はしません、判断材料の整理のみ）。

【前提】
・本業の有無：
・副業の売上（概算）：
・副業の経費（概算）：
・他に副業・収入があるか：

【出力形式】
・所得税の申告が必要になりそうな条件に当てはまるか（一般的な基準との比較。断定はしない）
・住民税は別途申告が必要になりやすい点の注意
・インボイス制度が関係しそうな場合の注意点
・不安な場合は税理士に確認すべき旨を明記
```

**ポイント**：「申告書の作成・提出代理」は税理士の独占業務。AIが担えるのは準備段階（証憑整理・仕分け・要否の目安整理）までという前提を毎回明記する。

## 本採用に向けた確認事項（ユーザー確認待ち）

- `収益トラッカー.md`のフォーマットを、請求書・仕分けの入力として使える形に調整が必要か（現状は問い合わせ管理用のため、品目・税区分などの列が無い可能性がある）
- freee・マネーフォワード等の会計ツールとのMCP連携まで踏み込むか、それとも「手元データを貼って下書きを作る」範囲に留めるか（後者の方が外部サービス連携のセットアップコストがなく、まず試しやすい）
- `gig-work-kit`/`spot-consulting-kit`のどちらに統合するか、独立スキルのままにするか（両方から収益データを受け取るため、現時点では独立スキルとして置いている）
