# 求人票フィット度スコア＋ATS調整ポイント（ドラフト）

既存の `company-scoring-sheet` は「企業」を2軸（本人適性・客観軸）で比較するためのもの。これに対して本スキルは**1件の求人票**を自分のCV・経歴と照らして採点し、「応募する価値があるか」「書類選考（ATS）を通るために職務経歴書のどこを調整すべきか」まで一歩具体的に踏み込む。`job-hunt-kit`②（企業別面接対策資料の差分カスタマイズ）の前段、応募するかどうかを決める段階で使う想定。

**既存スキルとの役割分担**：
- `company-scoring-sheet`：複数企業を横並びで比較・優先順位づけ（企業単位）
- `job-posting-fit-score`（本ドラフト）：1求人ごとの合否確度とCV調整点を出す（求人票単位）
- `job-hunt-kit`②：応募を決めた後の面接対策資料カスタマイズ

---

## ① 求人票フィット度スコア（10軸・A〜F評価）

**用途**：求人票を読んで「応募する価値があるか」を直感ではなく基準で判断する

**評価項目（各A〜Fの6段階）**
1. 必須スキル・経験の合致度
2. 歓迎スキルの合致度
3. 職種・ポジションレベルの合致度（経験年数・役職相当）
4. 業界・事業ドメインの経験合致度
5. 年収レンジと希望の合致度
6. 勤務条件（リモート可否・勤務地・勤務時間）の合致度
7. キャリア軸（`knowledge/user-profile.md`の転職活動の軸）との整合度
8. 求人票の具体性・信頼度（業務内容が具体的か、テンプレ的な抽象表現だけか）
9. 応募〜選考プロセスの負荷（必要な提出物・筆記試験等の有無）
10. 総合判定（上記9項目を踏まえた「応募すべきか」の最終評価）

各項目に評価（A〜F）＋一言根拠を添える。Dランク以下が3項目以上なら応募自体を再検討する、という目安を持つ。

**プロンプト**
```
以下の求人票を、私のCV・経歴と照らして10項目でA〜F評価してください。

【求人票】
（求人票の本文を貼る）

【私のCV・経歴の要約】
（職務経歴書の要約、または knowledge/user-profile.md の該当部分を貼る）

【評価項目】
①必須スキル・経験の合致度／②歓迎スキルの合致度／③職種・ポジションレベルの合致度／
④業界・事業ドメインの経験合致度／⑤年収レンジと希望の合致度／
⑥勤務条件（リモート可否・勤務地・勤務時間）の合致度／⑦キャリア軸との整合度／
⑧求人票の具体性・信頼度／⑨応募〜選考プロセスの負荷／⑩総合判定（応募すべきか）

各項目にA〜F＋一言根拠をつけ、Dランク以下が3項目以上ある場合はその旨を明示してください。
```

**ポイント**：採点を「良い気がする／悪い気がする」の直感で終わらせず、どの軸が弱いかを明示することで、②のCV調整が的確になる。採点結果は`応募企業一覧.xlsx`（`job-hunt-kit`④）に1行で転記できる粒度にしておく。

## ② ATS通過を意識したCV調整ポイント

**用途**：①の採点結果を踏まえて、職務経歴書のどこを求人票向けに調整すべきかを洗い出す

**やり方**
1. ①で弱いと判定された軸（特に①②③のスキル・経験系）を確認する
2. 求人票内のキーワード（必須スキル・歓迎スキル欄の語句）が、職務経歴書の中にそのまま/言い換えで存在するか確認する
3. 存在しない場合、誇張・経歴詐称にならない範囲で「実際に経験した業務のどの部分が該当するか」を言語化して追記する

**プロンプト**
```
以下の求人票に出てくる必須・歓迎スキルのキーワードと、私の職務経歴書を比較してください。

【求人票】
（貼る）

【現在の職務経歴書】
（貼る）

出力してほしいもの：
1. 求人票に出てくるが職務経歴書に無い・弱いキーワード一覧
2. それぞれについて、実際の経験から言える範囲で追記できる具体的な一文案
3. 事実にない経験を作り出すような提案は絶対にしないこと（既存の実績を言い換える・強調するだけに留める）
```

**ポイント**：ATS（採用管理システムによるキーワードマッチング選考）対策は「キーワードを入れる」こと自体が目的化すると経歴詐称のリスクに近づく。必ず「実際にやったことの言い換え」に限定し、最終判断はユーザー自身が行う。
