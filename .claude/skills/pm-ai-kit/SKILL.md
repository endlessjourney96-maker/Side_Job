# PM実務 AI活用キット

会議メモ、顧客への文面、比較検討、進捗報告など、PM/PL/フリーランス業務でよく発生する「考える前の下ごしらえ」をAIに任せるためのテンプレート集。

**共通ルール**：AIに任せるのは「たたき台づくり」まで。事実確認・言葉の最終調整・人間関係が絡む判断は必ず自分でやる。

**使うツール**：基本は Claude（claude.ai のチャット、または Claude Code のターミナル）。会議の音声メモから文字起こしが必要な場合は、iPhone標準のボイスメモ文字起こし機能、または Notta / Rimo などの日本語特化の文字起こしサービスを併用する。整理後のアウトプットは Notion または Google ドキュメントに貼って関係者と共有する。

---

## ① 議事録整理

**用途**：会議中の殴り書きメモを、共有できる議事録の形にする

**やり方**
1. 会議中はメモアプリ（iPhone標準メモ、または音声入力）に殴り書きでOK
2. 会議後すぐ、Claude のチャットを開き、下のプロンプトにメモを貼って送る
3. 出てきた議事録を Notion / Google ドキュメントに貼り、ToDo部分だけ目視確認してから共有する

**プロンプト**
```
以下は会議中に取ったメモです。議事録の形式に整理してください。

【出力形式】
・会議名/日時
・参加者
・決定事項（箇条書き）
・ToDo（誰が／何を／いつまでに）
・保留事項（次回への持ち越し）

【メモ】
（ここに殴り書きメモをそのまま貼る）

【注意点】
・メモにない内容は勝手に補わない
・曖昧な部分は「要確認」として明記する
・話者の意図を推測しすぎない
```

**ポイント**：「注意点」を必ず入れる。入れないとAIが親切心で「たぶんこういうことだろう」と補完し、事実と違う議事録になることがある。

## ② 言いにくいことを伝える文面

**用途**：納期相談、認識のズレの指摘など、気が重いビジネス文面の下書き

**やり方**
1. 伝えたいことを箇条書きでメモしておく（結論を先に決めておくのがコツ）
2. Claude に下のプロンプトで投げる
3. 出てきた文面は必ず自分の言葉に少し直してから送る（そのまま送らない）

**プロンプト**
```
以下の状況を、失礼のない丁寧なビジネス文面にしてください。

【状況】
（誰に、何を伝えたいか、背景を箇条書きで）

【トーン】
・謝罪ではなく事実ベースで伝えたい
・相手を責めるニュアンスは避けたい
・代替案があれば添えたい

【伝えたい結論】
（例：納期を3日延ばしてほしい）
```

**ポイント**：結論があいまいなまま投げると当たり障りのない長文になりがち。先に「最終的に何を伝えたいか」を決めてから頼む。

## ③ 比較検討のたたき台

**用途**：新しいツール・サービスを検討するときの一次整理

**やり方**
1. 比較対象を2〜3個に絞る（多すぎると精度が落ちる）
2. Claude に下のプロンプトで投げ、表形式で出力させる
3. 出てきた情報のうち「料金」「仕様」など事実部分は、必ず公式サイトで裏取りする（AIの知識は古い場合がある）

**プロンプト**
```
以下のツール/サービスについて、フリーランスが業務で使う観点で比較してください。

【比較対象】
A：○○
B：○○

【比較軸】
・料金
・学習コスト
・実務での具体的な使いどころ
・向いていない業務

【出力形式】
表形式で。最後に「個人的にはこちらがおすすめ」という一文も添えてください。
```

## ④ 進捗報告・週次報告の下書き

**用途**：週次/月次で提出する進捗報告書の下書き作成

**やり方**
1. その週にやったことを箇条書きでメモしておく（完了/未完了/困っていることを分けて書くと精度が上がる）
2. Claude に下のプロンプトで投げる
3. 数字や固有名詞は必ず自分でファクトチェックしてから提出する

**プロンプト**
```
以下は今週の作業メモです。進捗報告書の形式に整理してください。

【出力形式】
・今週の完了事項
・進行中の事項（進捗率の目安つき）
・課題/困りごと
・来週の予定

【メモ】
（今週やったこと・困ったことを箇条書きで貼る）

【トーン】
・淡々とした事実ベース。過度に謙遜も誇張もしない
```

## ⑤ 要件整理から仕様たたき台

**用途**：顧客・事業部門からのふわっとした要望を、仕様のたたき台に変換する

**やり方**
1. 聞き取った要望をそのままメモ（口頭の言い回しのままでOK）
2. Claude に下のプロンプトで投げる
3. 出てきたたたき台を持って、もう一度顧客に「この理解で合っていますか」と確認する（AIの整理をそのまま仕様化しない）

**プロンプト**
```
以下は顧客からヒアリングした要望のメモです。仕様のたたき台に整理してください。

【出力形式】
・要望の要約（顧客が本当に実現したいこと）
・実現するために必要な機能（箇条書き）
・不明点・確認が必要な点
・想定される懸念事項

【メモ】
（ヒアリングメモをそのまま貼る）
```

## ⑥ リスク・懸念点の洗い出し

**用途**：プロジェクトの節目で、見落としがちなリスクを一度棚卸しする

**やり方**
1. プロジェクトの現状（スケジュール、体制、外部依存など）を簡単にメモ
2. Claude に下のプロンプトで投げる
3. 出てきたリスクのうち、実際に対応が必要なものだけを自分で選別し、チームに共有する（全部を鵜呑みにしない）

**プロンプト**
```
以下はプロジェクトの現状メモです。プロジェクトマネジメントの観点でリスクを洗い出してください。

【出力形式】
・スケジュール面のリスク
・体制面のリスク
・外部依存（ベンダー/顧客都合）のリスク
・それぞれの発生確率（高/中/低の目安）と、簡単な対策案

【現状メモ】
（プロジェクトの状況を箇条書きで貼る）
```
