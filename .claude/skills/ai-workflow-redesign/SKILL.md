# AI時代の業務再設計フレームワーク

業務の担い手を「人 → 単純作業も複雑作業も全部担当」という前提から見直し、誰が・どこまで担うのが最適かを再設計する。[[dx-consulting-framework]]の①診断の後、改善案を作る段階で使う。

**背景となる考え方（3つの型）**
- 従来型：人がすべて担当
- セルフサービス型DX：単純・短時間作業を顧客側へ移す（セルフレジ、モバイルオーダーなど）。ただし「働く側から別の人へ負担を移しているだけ」という側面もある
- AIエージェント型DX：AIが「複雑だがルール化可能な作業」を担い、人は判断・交渉・創造・責任に集中する

**重要な思想**：「負担の移転」だけではDXとは限らない。理想は負担移転ではなく**負担消滅**（その作業自体をなくす）を目指すこと。

---

## ① 業務の役割再配分

**用途**：ある業務プロセスの各工程を洗い出し、それぞれ人・顧客・AI・システムの誰が担うべきかを再設計する

**やり方**
1. 対象の業務を工程単位に分解する（例：問い合わせ対応なら「受付→分類→一次回答→エスカレーション→クローズ」）
2. 各工程について、以下の順で検討する：
   - まず「この工程、なくせないか」を考える（負担消滅）
   - なくせないなら「ルール化できるか」を考える（AIに任せられるか）
   - AIに向かないなら「顧客自身にできる単純作業か」を考える（セルフサービス化）
   - どれも当てはまらなければ人が担当（判断・交渉・創造・責任が求められる部分）
3. 再設計後、「誰の負担が減り、誰の負担が増えたか」を必ず確認する（セルフサービス化は顧客に負担を移しているだけの場合があるため）

**プロンプト**
```
以下の業務プロセスを、工程ごとに分解し、それぞれ「なくせないか／AIに任せられないか／
顧客自身にできないか／人が担うべきか」の順で再設計してください。

【対象の業務プロセス】
（工程を箇条書きで貼る。無ければ大まかな流れだけでも可）

【出力形式】
・工程ごとの分解
・各工程の再配分案（消滅／AI／顧客セルフ／人、のどれか＋理由）
・再設計後、誰の負担が減り誰の負担が増えたか
・実行する場合のリスク・懸念点
```

**ポイント**：「AIに任せる」が目的化しないよう、必ず最初に「なくせないか」を検討させる。効率化の前に業務そのものの要否を疑うのが、このフレームワークの核。
