# AI時代の業務再設計フレームワーク

業務の担い手を「人 → 単純作業も複雑作業も全部担当」という前提から見直し、誰が・どこまで担うのが最適かを再設計する。[[dx-consulting-framework]]の①診断の後、改善案を作る段階で使う。

**背景となる考え方（3つの型）**
- 従来型：人がすべて担当
- セルフサービス型DX：単純・短時間作業を顧客側へ移す（セルフレジ、モバイルオーダーなど）。ただし「働く側から別の人へ負担を移しているだけ」という側面もある
- AIエージェント型DX：AIが「複雑だがルール化可能な作業」を担い、人は判断・交渉・創造・責任に集中する

**重要な思想**：「負担の移転」だけではDXとは限らない。理想は負担移転ではなく**負担消滅**（その作業自体をなくす）を目指すこと。

---

## ① 業務の役割再配分

**用途**：ある業務プロセスの各工程を洗い出し、それぞれ人・顧客・AI・システムの誰が担うべきかを再設計する

**やり方**
1. 対象の業務を**極小の動作まで**分解する（2026-09-13、ChatGPT壁打ちより）。「会議資料を作る」のような大きな単位ではなく、「前回資料を探す→数字を別システムで確認→Excelを開く→転記→グラフ更新→コメントを書く→上司へ送る→指摘を受ける→修正→PDF化→メール送付」のように、実際に手を動かす粒度まで書き出す。粒度の目安は「歯磨きをする」を「歯ブラシを取る→歯磨き粉を取る→キャップを開ける→出す→閉める→水を使う→磨く→すすぐ→片付ける」の9工程に分けるくらい細かく。ここまで分解して初めて「そもそも前回版を探す必要があるか」「数値取得と転記は同時にできないか」「持ち替え・移動の無駄はないか」という改善点が見える
2. 各工程について、以下の順で検討する：
   - まず「この工程、なくせないか」を考える（負担消滅）
   - なくせないなら「ルール化できるか」を考える（AIに任せられるか）
   - AIに向かないなら「顧客自身にできる単純作業か」を考える（セルフサービス化）
   - どれも当てはまらなければ人が担当（判断・交渉・創造・責任が求められる部分）
3. 再設計後、「誰の負担が減り、誰の負担が増えたか」を必ず確認する（セルフサービス化は顧客に負担を移しているだけの場合があるため）

**プロンプト**
```
以下の業務プロセスを、工程ごとに分解し、それぞれ「なくせないか／AIに任せられないか／
顧客自身にできないか／人が担うべきか」の順で再設計してください。

【対象の業務プロセス】
（工程を箇条書きで貼る。無ければ大まかな流れだけでも可）

【出力形式】
・工程ごとの分解
・各工程の再配分案（消滅／AI／顧客セルフ／人、のどれか＋理由）
・再設計後、誰の負担が減り誰の負担が増えたか
・実行する場合のリスク・懸念点
```

**ポイント**：「AIに任せる」が目的化しないよう、必ず最初に「なくせないか」を検討させる。効率化の前に業務そのものの要否を疑うのが、このフレームワークの核。

## ② 「回数を減らす」視点（2026-09-13、ChatGPT壁打ちより）

効率化というと「1回の作業を速くする」ことに注目しがちだが、メール・LINE・Slack・Teams・SNS・通知確認のような**小さな繰り返し行為の「回数」自体を減らす**方が効くことが多い。1回は数十秒でも、1日何十回・何年も繰り返せば大きな時間になり、しかも毎回「見る→判断する→元の作業へ戻る」というコンテキストスイッチのコストが発生する。

**チェックの仕方**：①の分解をした後、各工程に対して「これは何回発生しているか」「同じ情報を複数の場所で見ていないか」を聞く。

**プロンプト**
```
以下の業務・確認作業について、1回あたりの時間ではなく「発生回数」に注目して
見直してください。

【対象の業務・確認作業】
（例：メールチェック、通知確認、進捗確認ミーティング等）

【出力形式】
・1日/1週間あたりの発生回数の見積もり
・同じ情報を複数の場所・タイミングで重複して見ていないか
・回数そのものを減らせないか（頻度を下げる、まとめて処理する、通知を絞る等）
・「みんなやっているから」という理由だけで続けている可能性はないか
```

**「みんなやっている」を疑う**：頻繁な通知確認等は「仕事だから必要」「みんなやっているから普通」と思われがちだが、本当にその頻度が必要かは別問題。DXの出発点は、当たり前だと思っている行動の頻度を疑うこと。

**疲労・負荷は回数でも見る**：「今日は疲れた」を勤務時間の長さだけで説明せず、普段との違い（会議数・通知数・想定外対応・アプリ間移動・判断回数・中断回数）を比較すると、想像していなかった改善ポイントが見つかることがある。
