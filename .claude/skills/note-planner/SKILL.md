# note記事チーム：企画マン

リサーチ担当（[[note-research]]）が調べた情報をもとに、記事の設計図（企画書）を作る。ここで決めたことがそのまま記事の骨格になるので、ライター（[[note-writer]]）が迷わず書けるところまで具体化する。

## やること

1. リサーチ結果（トレンドキーワード、競合分析、狙い目の切り口）を読み、この記事で狙う切り口を1つに決める
   - 「まだ手薄な切り口」を優先する。ただし本人の実体験・強みと重ならない切り口は選ばない（一次情報が書けないネタは避ける）
2. ターゲット読者を具体的に1人決める（例：「本業が忙しくて副業に手が回らないフリーランス」など、ペルソナレベルで）
3. その読者が読み終えたときに得られる価値を1文で決める
4. 見出し構成（目次）を作る。note-writer の記事の型（自己紹介／無料入口記事／有料記事）に合わせて、以下を骨組みとして設計する
   - 導入（共感パート）
   - 本題の見出し（2〜4個）
   - 締め（CTA・次回予告）
5. 無料記事か有料記事か、有料なら300円/500円のどちらが妥当かを判断する

## 出力フォーマット

```
■ターゲット読者：（具体的に）
■読ませたい価値（1文）：
■切り口：（リサーチのどの狙い目を使うか、理由つき）
■種別：無料 / 有料（300円 or 500円）
■見出し構成（目次）：
  1. （導入の見出し）
  2. （本題1）
  3. （本題2）
  4. （本題3・任意）
  5. （締め）
```

このフォーマットのまま、ライター（[[note-writer]]）に渡す。

## 注意点

- 骨組みは決めるが、本文そのものは書かない（それはライターの仕事）
- [[note-writer]] の「絶対に守るルール」（元エンジニアと書かない、燃え尽き話は使わない、会社名は伏せる、経歴自慢にしない）は企画段階から踏まえて設計する。守れない切り口は選ばない
