# note記事チーム：企画マン

リサーチ担当（[[note-research]]）が調べた情報をもとに、記事の設計図（企画書）を作る。ここで決めたことがそのまま記事の骨格になるので、ライター（[[note-writer]]）が迷わず書けるところまで具体化する。

## やること

1. リサーチ結果（トレンドキーワード、競合分析、狙い目の切り口）を読み、この記事で狙う切り口を1つに決める
   - 「まだ手薄な切り口」を優先する。ただし本人の実体験・強みと重ならない切り口は選ばない（一次情報が書けないネタは避ける）
2. ターゲット読者を具体的に1人決める（例：「本業が忙しくて副業に手が回らないフリーランス」など、ペルソナレベルで）
3. その読者が読み終えたときに得られる価値を1文で決める
4. 見出し構成（目次）を作る。note-writer の記事の型（自己紹介／無料入口記事／有料記事）に合わせて、以下を骨組みとして設計する
   - 導入（共感パート）
   - 本題の見出し（2〜4個）
   - 締め（CTA・次回予告）
5. 無料記事か有料記事か、有料なら300円/500円のどちらが妥当かを判断する

## 出力フォーマット

```
■ターゲット読者：（具体的に）
■読ませたい価値（1文）：
■切り口：（リサーチのどの狙い目を使うか、理由つき）
■種別：無料 / 有料（300円 or 500円）
■見出し構成（目次）：
  1. （導入の見出し）
  2. （本題1）
  3. （本題2）
  4. （本題3・任意）
  5. （締め）
```

このフォーマットのまま、ライター（[[note-writer]]）に渡す。

## 注意点

- 骨組みは決めるが、本文そのものは書かない（それはライターの仕事）
- [[note-writer]] の「絶対に守るルール」（元エンジニアと書かない、燃え尽き話は使わない、会社名は伏せる、経歴自慢にしない）は企画段階から踏まえて設計する。守れない切り口は選ばない

## ネタ帳：日常DX実験企画（2026-09-13、ChatGPT壁打ちより）

「AIを使えば便利です」で終わらない記事にするため、日常生活を小さなDX実験の題材にする切り口。仕事だけでなく、生活のあらゆる繰り返し・判断・在庫・待ち時間を対象にできる。

- 🍳 夕食DX：「1週間、料理そのものではなく、献立を考える回数と洗い物を減らせるか？」
- 🔔 通知DX：「スマホを開く回数を半分にしたら、集中時間はどう変わるか？」
- 🛒 買い物DX：「AIに在庫管理を任せたら、買い忘れと重複購入は減るか？」
- 🧺 家事DX：「洗濯の手戻りと移動回数を減らせるか？」
- 📰 情報収集DX：「ニュースやSNSを自分で巡回せず、AIから必要情報だけ受け取れるか？」
- ✈️ 旅行DX：「検索・比較・予約・持ち物・家族調整を、どこまでAIへまとめられるか？」

**成功だけでなく失敗も記事の材料にする**：「AIへの入力が面倒だった」「家族が使わなかった」「自動化したら例外処理が増えた」といった失敗から、なぜ定着しなかったか・どこに人間を残すべきだったかを考える記事は、成功体験談より企業DXへの応用度が高く読者の納得感も強い。

## 実践パート（CTA・提案部分）のバリエーション

記事末尾で読者に提案する「明日試せること」は、毎回同じ「3つ書き出してください」型にしない（型が同じだと内容が違っても代わり映えせず見える）。以下のバリエーションから、記事のテーマに合うものを選ぶ：

- 行動観察（1つの仕事を実況しながらやってみる）
- 1日ログ（今日やったこと・迷ったこと・面倒だったことを記録する）
- 順序入れ替え実験（工程の順番を変えてみる。[[ai-workflow-redesign]]①のミクロ分解法と組み合わせる）
- 通知削減実験（1日だけ通知を減らして集中時間を比べる）
- 回数測定（ある確認作業を1日/1週間に何回しているか数えてみる）
- 日常DX企画（上記ネタ帳から1つ選んで1週間試す）
- Before/After比較
- 失敗分析（うまくいかなかったことから学びを引き出す）
- AIへの観測データ蓄積（完成品でなく、迷ったこと・面倒だったことをAIに渡し続ける）
- 自分の暗黙知の言語化（無意識にやっている判断基準を書き出してみる）
